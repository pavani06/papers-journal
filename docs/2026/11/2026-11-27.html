O dia foi dominado por benchmarks que expõem limites de avaliação e fronteiras mal governadas.

Hoje vale mais pela instrumentação do que por uma nova ideia de harness. Os melhores papers olham para onde agentes falham quando saem do sandbox: workflows longos entre plataformas, bancos de dados reversíveis ou não, regras em Markdown que não seguram fronteira nenhuma, e leaderboards cuja precisão estatística é menor que a diferença entre competidores.

OS-Omni: Benchmarking Generalist Computer-Using Agents on Long-Horizon Workflows Across Platforms

OS-Omni é relevante porque não mede só cliques isolados: mede workflows longos em Windows, Ubuntu, macOS, iOS, Android e Web, com estado persistente e avaliadores finais executáveis. O ponto que importa para você não é o ranking, mas a exposição de um regime onde a trajetória tem muitas chances de divergir antes do estado final.

Para o nosso casoUse como lembrete para não aceitar evals curtas demais no seu harness. Se uma skill ou subagente só é avaliado em tarefas de 10 passos, você ainda não sabe como ele preserva obrigações, estado e evidência em tarefas de 60 passos.

What a Forecasting Leaderboard Can Establish: Resolution Reporting for Zero-Shot Time-Series Models

O paper é sobre forecasting, mas a lição é geral para avaliação: um leaderboard pode ordenar modelos com uma precisão que seus próprios dados não suportam. A ferramenta Vernier calcula a resolução do board e mostra quando vizinhos no ranking são indistinguíveis, inclusive quando a ordem muda sem rerodar os modelos.

Para o nosso casoPara seus evals de agentes, trate diferença pequena como faixa de empate até provar o contrário. Um gate de adoção de skill ou prompt deveria reportar resolução mínima, não só média final.

Revisiting LLMs as Context Engineers

A mensagem útil é negativa: deixar o próprio LLM extrair instruções ou experiências de execuções offline não melhora de forma consistente. O achado mais acionável é a correlação negativa entre ganho e diversidade dos modos de falha; quando os erros são heterogêneos, o contexto sintetizado vira uma média ruim.

Para o nosso casoNo seu sistema, não trate skill autogerada como compilação confiável de experiência. Antes de promover uma skill, separe falhas por tipo; se o conjunto mistura causas diferentes, gere artefatos separados ou peça diagnóstico humano.

When an AI agent makes a mistake in a database, what decides the damage?

O estudo separa erro do modelo, guard layer e semântica do banco, o que é raro em incidentes com agentes. A conclusão mais importante é que engines diferem menos pelo que deixam destruir e mais pelo que permitem desfazer depois.

Para o nosso casoPara qualquer tool irreversível do seu harness, o gate principal não deve ser só “o modelo pediu algo perigoso?”. Deve ser “qual é o caminho de undo nativo, testado e registrado antes da ação?”.

Markdown Is Not a Firewall: four coding agents, one rules file, four boundaries

O paper testa uma suposição comum em agentes de código: colocar regras no repositório e esperar que isso funcione como controle. O resultado é ruim para essa prática: os agentes raramente transformam o arquivo em fronteira operacional, e em um caso o arquivo derruba desempenho sem melhorar segurança.

Para o nosso casoNão use rules.md como gate no seu sistema. Regras de repositório podem orientar estilo, mas fronteiras precisam estar fora do espaço que o agente edita: wrapper de ferramenta, verificador externo, log imutável e bloqueio executável.

estende o adiamento de compromisso para gates de segurança com ações graduadas e evidência auditável.

Guarding with Judgment: Learning to Intervene for Multimodal Safety

Embora o domínio seja segurança multimodal, a estrutura é boa para governança: allow, warn, review e refuse dependem de evidência, condição pendente e regra aplicada. Isso evita o binário fraco entre deixar passar e recusar quando falta uma verificação intermediária.

Para o nosso casoDá para copiar a taxonomia para gates humanos do seu harness: permitir, avisar, pedir revisão ou bloquear. O detalhe importante é registrar qual condição ainda precisa ser verificada, não só a decisão final.
