O dia favoreceu gates, curadoria e especificações: menos ação automática, mais seleção do que merece execução.

Foi um dia bom para quem opera harnesses, não para quem procura uma nova arquitetura milagrosa. O padrão mais útil apareceu em vários lugares: antes de executar, treinar, otimizar prompt ou agir proativamente, o sistema precisa decidir se aquela interação merece custo e autoridade. Isso conversa diretamente com o teu sistema, porque o gargalo não é throughput; é não desperdiçar a tua atenção nem registrar confiança onde só houve movimento.

Does Scaling Toward AGI Depend on What System-1 Lets System-2 Execute?

O paper mais votado do dia formaliza um loop predict-gate-execute-update: um componente barato estima utilidade, e o executor caro só age quando a margem compensa. A parte relevante não é a embalagem System-1/System-2, mas a noção de densidade de interações úteis como coordenada de eficiência. Isso dá linguagem matemática para uma decisão prática que teu harness já precisa tomar: quando chamar subagente, ferramenta cara ou raciocínio longo.

Para o nosso casoInstrumente o dispatch para registrar candidatos rejeitados, admitidos, custo e utilidade observada depois. Mesmo sem modelo treinado, uma regra calibrada por histórico pode virar gate explícito antes de execuções caras ou irreversíveis.

CEPO: A General Framework for Improving Prompt Optimization in Multi-Agent Systems

CEPO separa o prompt de coordenação do prompt de execução de cada agente, e otimiza cada parte segundo seu papel. A ideia é simples, mas boa: regras globais de roteamento, handoff e governança não deveriam ficar copiadas e divergindo dentro de cada subagente. O resultado experimental importa menos que a arquitetura de artefato: uma camada de coordenação versionada separadamente das skills executoras.

Para o nosso casoNo teu sistema, vale tratar instruções de dispatch como artefato próprio, com eval própria, em vez de deixá-las embutidas nas skills. Isso reduz conflito entre instruções locais e política global de delegação.

HALO: Human-Grounded Granular Evaluation of Proactive Agents

HALO é valioso porque não ranqueia modelos de forma genérica; ele nomeia o modo de falha. Em cenários que exigem evidência antes de decidir se deve ajudar, a maior parte das rejeições vem de over-proactivity: timing prematuro ou intensidade excessiva. Isso é exatamente o tipo de benchmark que muda gate, porque mostra que o erro não é só deixar de ajudar, mas ajudar sem mandato suficiente.

Para o nosso casoAdicione labels de timing e intensidade aos teus gates humanos, não apenas aprovado ou rejeitado. Para ações não solicitadas, exija evidência recuperada e um motivo explícito para não esperar.

GEPA-Curator: Curated Learning for Self Improving Agents

GEPA-Curator corrige uma ingenuidade comum em self-improvement: nem toda falha é bom material de aprendizado. Falhas podem vir de prompt ruim, harness ruim, juiz ruidoso ou aleatoriedade, e misturar tudo degrada a otimização. A contribuição prática é curar quais experiências entram no otimizador e recuperar trajetórias de sucesso anteriores como contexto.

Para o nosso casoNão alimente evolução de prompts ou skills com todo run malsucedido. Antes, classifique se a falha é atribuível ao artefato textual, ao ambiente, ao juiz ou à execução estocástica, e use sucessos passados como contraprova.

MemSteer: Turning User Histories into Supervision for Agent Memory Optimization

MemSteer pega históricos de usuário sem labels e gera pares pergunta-resposta com plano de evidência, auditoria por fonte e recuperação cega da resposta. O ponto bom é que a avaliação de memória não fica só em recuperar algo plausível; ela exige mostrar quais registros sustentam a resposta. Para teu caso, isso é mais interessante que mais uma memória longa: é um modo de fabricar eval de memória a partir dos próprios rastros.

Para o nosso casoUse logs antigos para gerar perguntas de memória com evidência esperada, e avalie store, retrieval e context construction sem mexer em pesos. A parte essencial é manter o plano de evidência, não apenas a resposta final.
