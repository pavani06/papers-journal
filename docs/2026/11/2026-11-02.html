O dia foi dominado por como escolher o que um agente deve aprender, executar ou esquecer.

Foi um dia bom para o teu problema real: não apareceu uma única grande resposta, mas vários papers cercaram o mesmo ponto operacional — a qualidade do agente depende menos de acrescentar mais skills, prompts e memória, e mais de decidir o que entra no loop de execução e no loop de aprendizagem. Os melhores trabalhos falam de retirada de skills, gates preditivos, separação entre prompt de coordenação e execução, curadoria de rollouts e avaliação de memória por evidência.

Destaques

R^2Orch: Recursive Self-Improvement for Agent Orchestration via Self-Play within a Skill-Internalization Loop

A ideia forte não é self-improvement genérico; é tratar skills como andaimes removíveis. O método escolhe tarefas em que a retirada de uma skill ainda muda o resultado, e remove a skill quando uma avaliação controlada mostra que o orquestrador já internalizou aquele comportamento. Isso é mais interessante do que acumular receitas, porque força o sistema a medir dependência real de cada skill.

Para o nosso casoNo teu harness, a tradução prática é rodar ablações periódicas de skills em tarefas arquivadas: se a skill não muda sucesso, custo ou evidência, ela deve virar candidata a remoção ou fusão. A ressalva é que isso só funciona se a avaliação por tarefa for estável o suficiente para distinguir skill inútil de juiz ruidoso.

Does Scaling Toward AGI Depend on What System-1 Lets System-2 Execute?

O paper formaliza o loop predict-gate-execute-update: um preditor barato decide quais interações merecem acionar o executor caro. A contribuição útil é deslocar a conversa de “mais raciocínio” para densidade de interações úteis, com arrependimento limitado por erro do preditor e margem de utilidade. Não é uma receita pronta de agente, mas é uma boa linguagem para desenhar dispatch.

Para o nosso casoVocê pode transformar o dispatch do harness em um gate explícito: para cada ação candidata, registrar utilidade prevista, custo previsto, decisão de executar ou não, e resultado observado. Isso cria dados para calibrar quando chamar subagente, ferramenta cara, verificador independente ou humano.

CEPO: A General Framework for Improving Prompt Optimization in Multi-Agent Systems

A tese é simples e operacional: prompt de coordenação e prompts de execução não devem ser otimizados como se fossem o mesmo artefato. CEPO mantém regras globais de coordenação em um prompt compartilhado e deixa instruções especializadas nos executores, usando otimizadores existentes por baixo. Isso conversa diretamente com sistemas em que uma correção de roteamento acaba sendo copiada manualmente para vários agentes.

Para o nosso casoVale revisar tua biblioteca de skills para separar três camadas: política de dispatch, contrato de handoff e instrução de execução. O ganho provável não é mágico; é reduzir drift entre subagentes quando você altera uma regra de coordenação.

When Requirements Interact: Scaling Long-Horizon Coding via Interdependent Specifications

CodeSpecWeave ataca exatamente a diferença entre satisfazer critérios locais e completar uma mudança de software coerente. O pipeline sintetiza tarefas com requisitos acoplados e testes executáveis, depois usa um agente revisor para auditar trajetórias e confiabilidade dos testes. O valor não está em mais um ranking de código, mas em explicitar que requisitos compostos precisam ser gerados e avaliados como dependências, não como lista plana.

Para o nosso casoPara teu sistema, isso sugere que evals de código devem incluir pares de requisitos que se condicionam: compatibilidade de interface mais tratamento de erro, refatoração mais preservação de comportamento, migração mais testes existentes. Se o agente passa em checks isolados, mas falha na interação entre eles, o harness precisa registrar essa classe de falha separadamente.

MemSteer: Turning User Histories into Supervision for Agent Memory Optimization

MemSteer transforma históricos não rotulados em pares pergunta-resposta com evidência de suporte, depois usa esses pares para otimizar desenho de memória, recuperação e construção de contexto. A parte importante é a auditoria source-grounded e a recuperação cega da resposta, que tentam evitar que a memória vire só um resumo conveniente. Isso é uma resposta prática ao problema recorrente de memória agentic esconder a evidência original.

Para o nosso casoVocê pode gerar evals de memória a partir dos próprios logs do harness: pergunta, resposta esperada, registros que sustentam a resposta e checagem de que a resposta ainda é recuperável sem vazar o gabarito no contexto. Isso ajuda a comparar store, retrieval e compactação sem depender de intuição.

GEPA-Curator: Curated Learning for Self Improving Agents

GEPA-Curator parte de uma observação que todo operador de agente reconhece: nem todo rollout fracassado ensina algo sobre o prompt. A falha pode ser do harness, da ferramenta, do juiz ou de estocasticidade, e alimentar tudo no otimizador contamina a atualização. A contribuição é separar curadoria de tarefas e recuperação de trajetórias bem-sucedidas antes de pedir que o otimizador reflita.

Para o nosso casoAntes de deixar um otimizador mexer em skills, classifique os rollouts por confiabilidade do sinal: falha reproduzível, falha de ferramenta, juiz duvidoso, sucesso anterior recuperável. Isso evita transformar ruído operacional em regra permanente no prompt.
