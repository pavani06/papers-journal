Harness-S: Learning from Sibling Harnesses for Generalizable Agent Training

A ideia forte é não procurar um harness universalmente melhor, mas manter variantes especializadas para resgatar falhas do harness base durante o treino. As trajetórias bem-sucedidas sob esses harnesses irmãos entram no RL, e a política depois volta a operar sob o harness original. Isso é mais interessante que autoevolução genérica porque preserva uma interface operacional fixa enquanto usa diversidade de execução como fonte de comportamento.

Para o nosso casoPara o seu sistema, a versão prática é manter variantes de skills ou loops como instrumentos de diagnóstico e recuperação, não necessariamente como runtime permanente. O ponto de arquitetura é registrar perfis comportamentais das variantes para decidir quando uma delas deve tentar resgatar uma falha.

Random Is Almost Enough? Stable and Low-Cost Benchmark Compression via BestRand

O resultado útil não é que benchmark pequeno funciona; é que o erro de estimar o benchmark completo tem cauda longa. Amostras aleatórias costumam ser boas, mas algumas erram muito, e essa instabilidade não desaparece só porque mais modelos entram na comparação. BestRand tenta manter o custo baixo da aleatoriedade reduzindo justamente os casos de erro extremo.

Para o nosso casoSe você comprime suas evals de agente, não trate uma amostra pequena como neutra por definição. Gere vários subconjuntos candidatos, estime risco de cauda e mantenha execuções completas periódicas como calibração, principalmente antes de promover mudanças de harness.

Decoupled Predictive Decision Making: A Shared Conditional Predictor for Agents

A tese é separar decisão de geração: o LLM fornece representação semântica, mas um previsor condicional compartilhado decide a partir de evidência histórica estruturada. Isso encaixa bem em tool choice, preferência entre candidatos e julgamento de raciocínio, porque todas viram consultas sobre estado, histórico e alvo. O ganho vem menos de prompt engineering e mais de transformar logs de execução em uma base de evidência consultável.

Para o nosso casoVale olhar para seus gates e dispatchers como problemas de previsão condicional, não como mais uma chamada textual ao modelo. A decisão de chamar subagente, aprovar uma ação ou revisar uma resposta pode usar o mesmo formato: evidência passada, consulta explícita e regra de decisão auditável.

Tools Need Not Speak in Text: Latent Context Compression for Agents

O paper ataca uma suposição central do harness comum: ferramenta precisa devolver texto inteiro para o agente. A compressão em tokens latentes não é diretamente compatível com uso por API, mas o critério de treino é importante: preservar a distribuição da próxima ação, não preservar semanticamente a observação. Isso muda o alvo de uma sumarização de tool output de fidelidade textual para suficiência operacional.

Para o nosso casoVocê provavelmente não vai injetar embeddings latentes em modelos de terceiros, mas pode roubar a métrica. Ao compactar outputs de ferramentas em texto, avalie se o resumo preserva a próxima decisão correta do agente, não se parece bonito para um humano.

Identically Trained Language Models Break on Different Jailbreaks

O achado é um alerta metodológico: dois modelos treinados com a mesma receita podem quebrar em jailbreaks diferentes só por causa da semente de pré-treino. A variação por semente supera bastante a variação por pós-treino, então um conjunto de ataques vencedor contra um checkpoint não é necessariamente robusto contra outro checkpoint aparentemente equivalente. Para quem consome modelo por API, isso importa porque atualizações silenciosas podem trocar o perfil de falha sem trocar a família pública do modelo.

Para o nosso casoNão congele uma suíte pequena de prompts adversariais como se ela medisse a política de segurança de uma família inteira. Em mudança de modelo ou versão, reamostre ataques amplos e registre quais prompts deixam de transferir; isso é telemetria de regressão, não curiosidade de safety.
