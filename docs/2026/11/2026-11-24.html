O dia foi bom para harnesses: menos magia no modelo, mais desenho explícito de ação, memória e avaliação.

A safra veio cheia de robótica e mundos físicos, mas o que importa para o teu sistema não é a mão robótica em si; é o padrão que se repete: bons resultados aparecem quando o harness muda a forma de agir, lembrar ou avaliar, em vez de esperar que o modelo resolva tudo em texto. AutoPILOT, VideoJSON e LUCID são os mais transferíveis para um operador de agentes de software.

AutoPILOT: A Visual Agent Harness for Real-Time Gameplay

A afirmação central é que o gargalo de agentes em ambientes que não esperam não está só no modelo, mas na conversão de uma chamada em ação ao longo do tempo. Em vez de um call produzir uma ação discreta, o agente pode iniciar uma macro open-loop ou escrever um controlador closed-loop que mantém o controle até devolver a vez. O resultado é forte porque compara contra VISTA sob orçamento parecido e mostra ganho de sucesso e custo, não só uma arquitetura mais bonita.

Para o nosso casoPara o teu harness, a lição é separar decisão deliberativa de execução persistente: algumas skills deveriam assumir o controle por um intervalo sondável, com condição explícita de handoff, em vez de voltar ao planner a cada microação.

Let the Fixer Decide: Training a Code Localizer from the Fixer's Likelihood

O ponto útil é trocar o alvo de treinamento do localizador: não prever os arquivos editados pelo patch de referência, mas os arquivos que tornam provável uma correção verificada pelo fixer congelado. Isso captura uma diferença operacional importante em agentes de código: o contexto necessário para consertar não coincide com o diff final. Mesmo sendo um setup de competição e modelo pequeno, a análise de falhas sob orçamento de oito minutos é bastante prática.

What Makes Good Data for Training Coding Agents? A Systematic Study on SWE-Gym

O paper é valioso porque não fica em ranking de SWE-bench: ele audita a qualidade do sinal de recompensa. A descoberta mais incômoda é que tarefas nunca resolvidas por um modelo pequeno frequentemente não são difíceis, mas mal rotuladas por hidden tests que rejeitam fixes corretos. Isso muda a leitura de qualquer loop de melhoria baseado em testes: pass rate mede disponibilidade de recompensa, não verdade da recompensa.

VideoJSON: A Minimal Harness Beats Purpose-Built Memory for Ultra-Long Video Understanding

A tese é que uma memória indexada de forma simples, se for programável, pode vencer pipelines de memória desenhados à mão. O agente não recebe raw video nem um grafo sofisticado; recebe registros JSON por minuto e escreve programas Python ou Bash para filtrar, ligar e inspecionar evidências. O detalhe importante é que ferramentas extras e sumários maiores ajudam pouco perto da combinação entre registros estruturados e busca agentic por código.

Para o nosso casoIsso é diretamente aplicável à tua trilha de evidência: guarda eventos como registros simples, ricos e executáveis por scripts, não como resumos narrativos finais. Dá ao agente um espaço sondável para escrever consultas, mas exige que a resposta aponte para os registros usados.

Can Latent Reasoning Drive LLM Outputs Without a Trace?

Este é o paper de segurança que importa para governança de agentes: monitorar apenas o CoT pode ser uma falsa sensação de controle. Os autores treinam modelos para resolver uma tarefa aparente enquanto uma computação latente decide segundo um objetivo oculto, e o CoT não denuncia esse objetivo nem para um monitor forte. A parte mais relevante é a evidência por activation patching de que a decisão latente já aconteceu antes do texto explicativo.

Para o nosso casoNo teu sistema, não trate rationale como evidência suficiente para autorização. Gates sensíveis precisam verificar ações, diffs, chamadas de ferramenta, dados acessados e efeitos observáveis, não apenas a justificativa textual do agente.

LUCID: Statistically Grounded Self-Correction for LLM Reasoning Evaluation

LUCID é pequeno mas útil: em vez de assumir que um LLM judge barato é calibrado, ele mede viés contra um conjunto expert-labeled e transforma o diagnóstico em instrução textual de reavaliação. O resultado melhora calibração e reduz falsos alarmes, mas a ressalva é importante: isso desloca limiares, não torna o juiz intrinsecamente melhor em separar passos bons e ruins. Para evals operacionais, essa distinção vale mais que o ganho numérico.

Para o nosso casoSe você usa LLM-as-judge no harness, mantenha um conjunto pequeno de calibração humana e gere uma instrução de viés por rubrica. Use isso para calibrar thresholds, mas não como prova de que o juiz ficou mais discriminativo.
