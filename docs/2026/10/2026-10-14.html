O dia foi dominado por uma mesma pressão: transformar agentes em sistemas verificáveis, não só mais treinados.

generaliza a fragilidade de decisões tipadas para ordem, ausência de resposta e crescimento do conjunto de opções.

Jeva: System One Models from First Principles

A afirmação central é que transformar uma decisão estruturada em texto serializado é uma má interface: a ordem das opções vaza, o conjunto de candidatos não escala bem e a ausência de resposta se mistura com incerteza. Jeva aparece como uma arquitetura decision-native, não como mais um prompt ou reranker. O motivo para entrar é menos a chance de você usar o modelo e mais a popularidade: com quase 400 votos, essa linguagem de System One para decisões tipadas deve virar referência comum.

Para o nosso casoPara o seu harness, a lição prática é separar “nenhuma opção serve” de “não sei qual opção serve” nos dispatches. Também vale auditar qualquer gate baseado em lista de opções para invariância à ordem.

Harness^2: Recursive Agent Harnessing for an Open World

Harness² é diretamente no seu eixo: não tenta só treinar o agente, tenta evoluir o harness que decide como ele age. O ponto novo é atacar o caso mais incômodo, open-world sem ground-truth verifier, usando Propose-Probe-Compose para testar edições de harness antes de compô-las. Avança 05/10

identifica a agregação aditiva como mecanismo de crédito vazio e propõe agrupamento conjuntivo.

Scoring Higher, Answering Worse: Mitigating Reward Hacking in Rubric-Based RL via Protocol-Level Rubrics

O paper é importante porque desloca a culpa da rubrica em si para a forma de agregação. Uma soma ponderada deixa o modelo comprar pontos com comportamento periférico, mesmo quando erra a decisão que deveria ser obrigatória. Protocol-level Rubrics mudam a regra: dimensões contam só quando seus critérios necessários passam juntos e cláusulas de falha não disparam.

Para o nosso casoNos seus evals, pare de tratar checklist como soma inocente quando houver condições indispensáveis. Transforme rubricas críticas em gates conjuntivos: se faltou evidência, se violou escopo, ou se não executou teste obrigatório, o bloco inteiro falha.

Last Secure Code Benchmark: Is the Code You Vibe Secure?

Esse benchmark vale pelo modo de falha: as tarefas pedem funcionalidade e nunca mencionam segurança, exatamente como muita demanda real chega ao agente. Os agentes passam funcionalmente em 73,6% a 91,3% das tarefas, mas o melhor só entrega código funcional e seguro em 25,1%. Isso é mais útil do que outro ranking SWE porque expõe uma lacuna entre “funcionou” e “pode entrar no repositório”.

Para o nosso casoNo seu sistema, segurança precisa ser gate próprio, não subproduto dos testes. Para mudanças em código sensível, registre evidência de análise de CWE ou rode ferramenta estática antes de aceitar a conclusão do agente.

Avança 07/10

localiza a falha intermediária na escolha do próximo subobjetivo apesar de leitura factual correta.

Reading Right, Acting Wrong: Diagnosing Decision Failures of System One Models in Agent Loops

Esse é um diagnóstico bom porque separa percepção de decisão. Em vários estados de agente, modelos erram a próxima ação mesmo quando respondem corretamente a probes factuais sobre o mesmo estado. A falha dominante não é falta de informação, mas composição do próximo subobjetivo.

Para o nosso casoAntes de trocar modelo por achar que ele “não entendeu o contexto”, adicione um probe de subgoal: “qual obrigação aberta controla a próxima ação?”. Para dispatch e gates, isso sugere verificar o subobjetivo escolhido, não só os fatos recuperados.

Judges Follow the Reference: The Derivation Gap in Verifying Tool-Call Arguments

Esse é pequeno em votos, mas muito acionável. O resultado mostra uma derivation gap: julgadores aceitam menos argumentos corretos quando o valor precisa ser inferido, vem de default ou foi cortado do input. Pior, em teste controlado eles seguem uma referência incorreta visível contra uma correta escondida.

Para o nosso casoAo julgar tool calls, não peça ao juiz para inferir defaults e valores derivados no mesmo passo em que avalia o candidato. Gere antes uma referência derivada a partir do histórico completo, sem ver o candidato, e só então compare.
