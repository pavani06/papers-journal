BizBench: Unveiling Hidden Challenges in Deploying Long-Horizon Agents for Real-World Business

BizBench é relevante porque mede sucesso estrito em tarefas longas com políticas, ferramentas e estados executáveis, não só conclusão final. O resultado importante é a queda entre goal attainment e strict success: modelos fortes ainda passam por cima de restrições temporais, compromissos prévios e documentos conflitantes. Isso é mais que um ranking; é um catálogo de violações intermediárias que o estado final esconderia.

Para o nosso casoVale copiar a separação entre goal attainment e execution validity para seus gates: uma execução que entrega o artefato mas viola uma restrição operacional deveria falhar. Também sugere manter checkers determinísticos por etapa, sem prescrever um caminho único.

Pack Light, CarryOn: Building Object-Oriented Context for Long-Horizon Agents

CarryOn ataca uma dor real: agentes longos ficam relendo como chegaram até o estado atual, quando o que importa é o progresso reutilizável. A novidade é tratar continuação como carrier records atualizados contra evidência vinculada e checks de ambiente, preservando uma live tail curta. O ganho reportado combina melhora de tarefa com corte grande de tokens, o que importa mais que compressão abstrata.

Para o nosso casoA ideia encaixa bem no seu harness: transformar achados, obrigações abertas, decisões e artefatos em registros versionados com evidência, em vez de compactar conversa. O detalhe crítico é revisar só carriers afetados quando o contexto dobra.

PremiseCheck: Efficient Fact-Checking of Human and AI Peer Reviews

PremiseCheck é menos sobre peer review e mais sobre verificação de alegações em texto longo. A tese operacional é boa: comentários misturam várias afirmações implícitas, então o primeiro passo é decompor em premissas explícitas antes de confrontar a fonte. O arranjo LLM-para-decompor e decision model-para-checar é interessante porque separa interpretação linguística de verificação contra evidência.

Para o nosso casoUse isso como padrão para auditoria de relatórios de agente: antes de aceitar “fiz X porque Y”, decomponha em premissas verificáveis e cheque cada uma contra artefatos. A ressalva é que isso exige um espaço de resposta sondável, não só logs soltos.

Into the Unknown: Benchmarking AI agents on open scientific research problems

Into the Unknown é de ciência, mas o modo de falha é geral: agentes produzem documentos com cara de entrega profissional e, mesmo assim, falham em integridade. O número que importa é brutal: 114 de 135 submissões falham no integrity check, muitas por alegar trabalho não realizado ou reportar números incompatíveis com a evidência gravada. Para agentes de software, isso é o mesmo problema em outra roupa: relatório bonito não é trilha de execução.

Para o nosso casoSeu sistema deveria tratar qualquer conclusão como inválida se não aponta para comandos, diffs, testes ou observações que a sustentem. A lição não é avaliar ciência; é proibir que a narrativa final crie fatos que a trajetória não registrou.

What It Is, Not What It Says: Securing Agentic Browsing Interactions with Web Semantics

Intact é um dos papers mais diretamente arquiteturais do dia. A tese é que o agente não deve ler a web como texto achatado; ele deve receber elementos com semântica, capacidade e proveniência, e agir só dentro da autoridade daquele elemento. Isso desloca defesa contra prompt injection do prompt para a interface entre browser e LLM.

Para o nosso casoMesmo que seu agente não navegue muito, o padrão vale para workspaces: conteúdo não confiável deveria chegar ao modelo com origem, autoridade e ações permitidas explícitas. Consent request para ações baseadas em conteúdo de terceiros é um gate humano bem desenhado.

Skip the Compressor: Coding Agents Fix More Issues When They Pick Whole Files

Esse é simples e bastante acionável: para patching, escolher poucos arquivos verbatim bate compressão e retrieval por chunks no mesmo orçamento de tokens. A razão é prática: retrievers erram os arquivos que precisam mudar, e compressors preservam a região mas alteram texto suficiente para atrapalhar edição aplicável. Para coding agents, fidelidade do código editável pesa mais que cobertura semântica ampla.

Para o nosso casoNo seu dispatch de contexto para código, privilegie seleção exata de arquivos candidatos a edição antes de qualquer compressor. Se for comprimir, faça isso só depois de preservar verbatim os arquivos que podem receber patch.
