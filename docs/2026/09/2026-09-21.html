Avança 17/09

estende para repositórios gerais e extrai tarefas apenas da funcionalidade implementada, sem depender de artefatos de desenvolvimento.

CodeMidas: Scaling Agentic Coding RL Environments from Code Itself

CodeMidas usa o próprio código como fonte para formular especificações comportamentais, construir testes contra a implementação original e filtrar tarefas por rollouts repetidos. A parte relevante não é o ganho em benchmarks, mas a escala de ambientes verificáveis sem depender de issues, commits ou tarefas humanas previamente escritas.

Para o nosso casoMesmo sem treinar modelo, a ideia serve para gerar evals internas: escolher funcionalidade implementada, pedir ao agente para inferir contrato, construir testes contra o comportamento atual e só aceitar tarefas que sobrevivem a execuções repetidas. Isso é um caminho barato para transformar teu próprio repositório em banco de regressões agentic.

Grounded Skill Synthesis from Code at Scale for Agentic Intelligence

Code2Skill transforma unidades de código em operações, workflows e padrões reutilizáveis, com metadados de fronteira, proveniência e evidência. O ponto novo é tratar código como fonte de skills grounded, não como documentação solta nem como trajetória observada de um agente.

Para o nosso casoVale copiar o critério de aceitação: uma skill só entra se puder ser reconstruída sem ver o corpo-fonte e depois comparada com ele. Para skills versionadas no teu harness, isso sugere um gate de publicação que exige evidência de reconstrução, fronteiras explícitas e proveniência, não apenas uma boa descrição textual.

EvoOntology: A Self-Evolving Ontology Layer for Data Agents

EvoOntology coloca a camada semântica como um servidor MCP com schema, conteúdo e ferramentas, em vez de despejar ontologia no prompt. A evolução contínua passa por edições tipadas guiadas por atribuição e aceitas apenas após avaliação pareada condicionada ao modelo-base.

Para o nosso casoA transferência para o teu sistema é arquitetural: memória e semântica operacional deveriam ser consultáveis como ferramenta, não apenas pré-injetadas em contexto. O gate de edição pareada também é um bom padrão para mudanças em skills ou dispatch: aceitar só quando corrige sem piorar casos comparáveis.

Avança 17/09

RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents

RecreationWorld força o agente a observar uma aplicação em execução, reconstruir seu comportamento e validar visualmente o artefato, atravessando GUI, código e linha de comando. O oráculo é a própria referência rodando, com testes comportamentais ocultos e assertions visuais/programáticas.

Para o nosso casoIsso reforça uma regra para evals do teu harness: tarefas boas não devem especificar todo o comportamento, devem exigir descoberta e comparação contra um oráculo executável. Também sugere medir se o agente verifica o output renderizado, não só se escreveu código plausível.

Avança 18/09

adiciona tráfego real, memória procedural externa e um replay gate que bloqueia regressões observadas.

Designer-RSI: Evolving Procedural Memory from User Traffic for Agentic Graphic Design

Designer-RSI mantém o modelo congelado e adapta uma memória procedural de skills a partir de briefs reais, ampliando cobertura e revisando procedimentos existentes. O detalhe importante é o matched replay gate: mudanças só entram se repararem falhas sem regredir sucessos observados.

Para o nosso casoEsse é diretamente aplicável ao teu fluxo de skills: separar widening, para subtarefas recorrentes sem cobertura, de deepening, para skills que falharam em execução. O replay gate é o antídoto contra auto-melhoria textual que parece boa mas apaga comportamento que já funcionava.

Avança 09/09

estende a tese para pagamentos agentic e quantifica a diferença entre solicitação do modelo e autorização efetiva.

APort Vault: Benchmarking AI Agent Payment Authorization with the Open Agent Passport

APort Vault é pequeno em votos, mas é o paper mais limpo do dia sobre fronteira de autoridade. O resultado separa pedido do modelo e autorização efetiva: modelos ainda emitem solicitações perigosas sob ataque, enquanto uma checagem determinística pré-ação zera transferências fora do passaporte permitido no recorte medido.

Para o nosso casoPara o teu harness, isso é argumento contra confiar em prompt de política para ações irreversíveis. A política crítica precisa virar pre-action check determinístico, com log separado do que o modelo pediu e do que o gate autorizou.
