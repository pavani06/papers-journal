O dia foi forte em ambientes verificáveis e camadas externas para agentes, menos em modelos novos.

O padrão do dia é claro: em vez de apostar que o modelo vai “entender melhor”, vários papers empurram confiabilidade para artefatos externos — ontologias consultáveis, skills verificadas, ambientes executáveis, referências rodando como oráculo e checks determinísticos antes de ação sensível. Isso conversa diretamente com o teu harness: a vantagem não está em mais uma cadeia de pensamento, mas em transformar estado, memória, autorização e avaliação em objetos sondáveis.

EvoOntology: A Self-Evolving Ontology Layer for Data Agents

A ideia forte é tratar a camada semântica como um servidor MCP vivo, não como texto colado no prompt. A ontologia tem schema, conteúdo e ferramentas, e evolui por edições tipadas aceitas só depois de avaliação pareada condicionada ao backbone. O paper entra também pelo piso de popularização: 149 upvotes num tema de agentes de dados já o tornam referência que você deve conhecer.

Para o nosso casoPara o teu sistema, a parte aproveitável é a separação entre conhecimento operacional consultável e contexto injetado. Se uma skill ou memória começa a virar prompt longo demais, a alternativa é expô-la como camada interrogável com edições auditáveis e teste pareado antes de aceitar mudança.

CodeMidas: Scaling Agentic Coding RL Environments from Code Itself

CodeMidas extrai tarefas não de issues ou commits, mas do comportamento já implementado no código. O pipeline explora funcionalidade, formula especificações comportamentais, constrói testes contra a execução original e filtra tarefas por rollouts repetidos. Para você, o valor não está em treinar MiMo, e sim no método de transformar repositórios comuns em evals executáveis com verificador confiável.

Para o nosso casoDá para roubar a receita para criar regressões do teu harness: escolher funcionalidade real, gerar especificação comportamental, ancorar em execução conhecida e só aceitar tarefas que sobrevivem a tentativas repetidas de solução. Isso é melhor do que manter uma coleção manual de prompts “representativos”.

Grounded Skill Synthesis from Code at Scale for Agentic Intelligence

Code2Skill ataca uma limitação prática das skill banks: trajetórias são caras e documentos não provam executabilidade. O pipeline extrai operações, workflows e padrões a partir de unidades de código, depois verifica por reconstrução sem ver o corpo original e comparação com a fonte. O resultado é menos interessante como “um milhão de skills” e mais como formato: skill com fronteira, proveniência, workflow e evidência de origem.

Para o nosso casoO teu repositório de skills deveria registrar evidência de grounding, não só instrução natural. A checagem por reconstrução cega é uma boa inspiração para testar se uma skill contém procedimento suficiente ou apenas descreve vagamente uma prática.

RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents

RecreationWorld força o agente a observar uma referência em execução, descobrir comportamento e construir uma implementação fiel, alternando GUI, código e verificação visual. O benchmark é melhor que um ranking de computer-use porque usa a referência como oráculo para testes ocultos e assertions visuais condicionadas a ações. Isso mede uma falha importante: agentes que editam código ainda evitam ou executam mal a verificação do artefato renderizado.

Para o nosso casoSe teu agente produz artefatos interativos, o gate não deveria parar em teste unitário ou diff textual. Vale adicionar tarefas em que o agente precise comparar comportamento observado contra implementação própria e registrar evidência visual ou programática de equivalência.

estende a vantagem de política determinística para autorização de pagamentos agentic sob ataques humanos.

APort Vault: Benchmarking AI Agent Payment Authorization with the Open Agent Passport

APort Vault é pequeno em upvotes, mas importante para governança: 225 mil avaliações de ataques reais contra um agente de pagamento mostram que o modelo ainda solicita transferências perigosas sob certas políticas. A camada determinística de pre-action check zera transferências para destinatários não permitidos nas comparações reportadas, enquanto o modelo sozinho deixa passar violações. A lição não é “este padrão OAP venceu”, é que autorização deve ser fronteira executável, não instrução no prompt.

Para o nosso casoNo teu harness, qualquer ação irreversível precisa de um validador determinístico com objeto de autorização explícito antes da tool call. O modelo pode pedir; o gate decide se a ação pertence ao passaporte operacional daquela execução.

CADWorld: Computer-Use Benchmark for Long-Horizon Computer-Aided Design

CADWorld é um benchmark de computer-use em FreeCAD, mas o ponto transferível é a avaliação por artefato salvo: geometria, estrutura paramétrica, constraints, CAM, FEM e desenhos técnicos. O resultado separa agentes fracos, que nem produzem artefato válido, de agentes melhores, que passam a falhar em requisitos estruturais e de processo. Isso é o tipo de benchmark que revela modo de falha, não só placar.

Para o nosso casoAplique a mesma distinção nos teus evals de software: sucesso não é apenas “rodou” ou “testes passaram”, mas se o artefato final preserva estrutura, intenção e estado downstream. Bons gates devem verificar propriedades internas do resultado, não apenas a última ação do agente.
