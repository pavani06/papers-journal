O dia foi de transformar artefatos existentes em infraestrutura verificável para agentes.

Foi um dia forte para quem opera harness de agentes: vários papers atacam a mesma fronteira prática, que é tirar conhecimento de código, tráfego real, dados heterogêneos ou referências executáveis e convertê-lo em camada consultável, skill, ambiente de treino ou gate. Não é uma safra de prompts bonitos; é uma safra de mecanismos externos ao modelo, com avaliação pareada, provenance, testes executáveis e checks determinísticos.

EvoOntology: A Self-Evolving Ontology Layer for Data Agents

A afirmação central é que agentes de dados não devem explorar fontes brutas nem carregar uma camada semântica fixa no prompt; devem consultar uma ontologia viva em runtime. O detalhe importante é a ontologia empacotada como servidor MCP, com camadas de schema, conteúdo e ferramentas, e refinamento por edits tipados aceitos apenas após avaliação pareada condicionada ao backbone. O upvote alto também torna este paper referência provável na conversa de data agents.

Para o nosso casoPara o teu sistema, a lição é tratar semântica de ambiente como ferramenta versionada e consultável, não como contexto permanente. O padrão de aceitar mudanças na camada semântica só depois de avaliação pareada é diretamente aproveitável para skills e memória persistente.

CodeMidas: Scaling Agentic Coding RL Environments from Code Itself

A contribuição não é mais um benchmark de coding, mas uma fábrica de ambientes: agentes extraem comportamento implementado, formulam specs, constroem testes contra o código original e filtram tarefas por execução e rollouts repetidos. Isso muda a fonte de tarefas de treino: em vez de depender de issues, PRs e histórico humano, o próprio corpo do código vira gerador de trabalho verificável. O resultado importa mesmo para quem não treina modelo, porque mostra uma metodologia robusta para transformar repositórios em tarefas avaliáveis.

Para o nosso casoVocê pode roubar o pipeline como padrão de eval interno: escolher funcionalidades existentes, gerar specs comportamentais, construir testes contra a versão de referência e só admitir tarefas que sobrevivem a rollouts repetidos. Isso é mais útil do que inventar tarefas manuais para medir teu agente de código.

Designer-RSI: Evolving Procedural Memory from User Traffic for Agentic Graphic Design

APort Vault: Benchmarking AI Agent Payment Authorization with the Open Agent Passport

Este é o paper mais diretamente governança do dia: agentes sob ataque pedem transferências com frequência, e a fronteira real não é o pedido, é a autorização. O resultado forte é que a camada determinística baseada no Open Agent Passport zera transferências para recipientes não permitidos nos pares comparáveis, enquanto modelo sozinho ainda deixa passar casos. A honestidade metodológica de reportar eventos separados também é boa: colapsar tudo em um único número esconderia onde o sistema realmente falha.

Para o nosso casoNo teu sistema, ações irreversíveis devem passar por policy determinística externa ao modelo, com escopo assinado e checagem imediatamente antes da ação. Não peça ao agente para ser a autoridade final sobre aquilo que ele mesmo está tentando executar.
