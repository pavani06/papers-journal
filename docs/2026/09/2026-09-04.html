O dia foi forte em ambientes, contexto e avaliação de agentes, mas boa parte ainda mira treinamento, não operação.

Hoje teve pesquisa útil para o seu sistema, mas com uma divisão clara: os trabalhos mais populares estão tentando transformar artefatos de agente em coisas reutilizáveis — funções locais, ambientes terminais, memórias latentes — enquanto os trabalhos mais diretamente operacionais aparecem com menos voto. O ponto comum que vale levar para o café é simples: traces e contexto estão deixando de ser resíduo de execução e virando substrato para compilação, avaliação e geração de novas tarefas.

O que faltou foi governança humana prática. Houve um paper sobre conflitos personalizados, mas nada muito forte sobre quando interromper um agente, pedir aprovação ou registrar autoridade de decisão. Em compensação, RealSWE e AutoTraceGT são bem próximos do seu cotidiano: um mostra que benchmarks de código ainda dão contexto demais em linguagem limpa demais; o outro oferece um jeito disciplinado de transformar trajetória em taxonomia de falhas, sem fingir que um classificador prévio já sabe o que procurar.

Compile by Training: Turning Natural-Language Specifications into Local Neural Functions

A afirmação central é que uma especificação em linguagem natural pode ser compilada em uma pequena função neural executável localmente, em vez de chamar um modelo grande a cada uso. O ganho conceitual é tratar certas skills textuais recorrentes como artefatos armazenáveis, versionáveis e componíveis, mais próximos de software do que de prompt solto. A ressalva é que isso envolve treino/adaptação local e custo de compilação, então não encaixa imediatamente em um harness que consome modelos só por API.

Para o nosso casoVale como direção de arquitetura para skills estáveis e muito repetidas: primeiro medir quais chamadas do seu sistema são funções textuais recorrentes, depois decidir se merecem virar artefato compilado quando a infraestrutura permitir. Hoje, o aproveitamento mais realista é conceitual: separar skills que precisam de deliberação das que são apenas transformação semântica repetida.

quantifica que a escolha dos tokens intermediários pode ser quase aleatória quando o prompt é preservado.

Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning

O resultado forte é que, para compressão de KV cache em raciocínio longo, selecionar tokens intermediários com heurísticas sofisticadas quase não ajuda se o prompt estiver preservado. A explicação é operacionalmente interessante: o trace de raciocínio tem redundância textual e redundância entre heads, enquanto o prompt é a parte frágil. Isso desloca a pergunta de “qual token de raciocínio é importante?” para “o contrato inicial continua inteiro e acessível?”.

Para o nosso casoMesmo sem controlar KV cache via API, isso reforça uma regra para context engineering: preserve instruções, objetivo, constraints e evidência original com mais zelo do que resumos intermediários de pensamento. Em compactações de handoff, trate o prompt/contrato como região protegida, não como mais um item no orçamento.

LatentPress: Context Compression Beyond Text and Vision

A contribuição é uma interface de memória que não passa por texto resumido nem por imagem renderizada: um writer pequeno produz tokens contínuos consumidos pelo decoder congelado. O resultado reportado é forte porque a compressão 4–16x preserva ou até supera leitura de contexto bruto em alguns cenários, enquanto resumos textuais ficam muito atrás. Para operação por API, o obstáculo é óbvio: você provavelmente não consegue injetar embeddings diretamente no modelo de terceiros.

Para o nosso casoNada para implementar amanhã se o provedor não expõe soft tokens. Mas vale guardar a tese: memória para máquina não precisa ser legível por humano; no seu sistema, isso sugere separar memória auditável de memória otimizada para consumo do modelo quando a plataforma permitir.

RealSWE: A Compositional Evaluation of Coding Agents under Realistic User Requests

RealSWE mostra uma falha de benchmark muito concreta: SWE-bench dá aos agentes problemas longos, formais e ricos em informação, enquanto usuários reais pedem coisas curtas, casuais e incompletas. A queda média de resolução não é enorme, mas é suficiente para mudar ranking de modelos e, mais importante, para identificar quais informações realmente ajudam. Desired Behavior e Motivation importam; Environment Information e Reproduction Steps, no estudo, só adicionam tokens sem ganho mensurável.

Para o nosso casoIsso é diretamente aplicável ao seu planejador inicial: quando o pedido vier vago, priorize extrair comportamento desejado e motivação antes de pedir logs ou detalhes de ambiente por reflexo. Também vale criar evals internas com variantes casuais e subespecificadas do mesmo patch, não só issues bem escritas.

Using Grounded Theory for Agent Behavior Analysis at Scale

AutoTraceGT importa porque trata análise de trajetória como descoberta qualitativa escalável, não como classificação em uma lista de falhas decidida antes. O pipeline automatiza open, axial e theoretical coding até saturação, produzindo codebooks por tarefa que recuperam boa parte das taxonomias humanas e ainda encontram padrões extras. O ponto forte para observabilidade é a trilha auditável entre trace bruto, código comportamental e narrativa teórica.

Para o nosso casoVocê pode adaptar a ideia sem comprar o pacote inteiro: amostrar traces, gerar códigos comportamentais emergentes, agrupar por relações causais e só então transformar isso em rubricas ou gates. É uma alternativa melhor do que começar com uma taxonomia fixa de “falhou por planejamento, ferramenta ou contexto” e encaixar tudo à força.
