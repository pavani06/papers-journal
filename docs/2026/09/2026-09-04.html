Compile by Training: Turning Natural-Language Specifications into Local Neural Functions

A ideia forte é tratar uma especificação textual recorrente como algo compilável: um professor gera exemplos, um adaptador pequeno aprende a função, e o resultado vira artefato armazenável e componível. Isso não substitui uma skill agentic aberta; serve para funções textuais estreitas, fuzzy e repetidas, onde regras manuais são frágeis e chamar um modelo remoto toda vez é desperdício. Entrou como destaque também pelo piso de popularização: 256 upvotes tornam provável que isso vire referência comum.

Para o nosso casoNo teu harness, a leitura útil é separar skills abertas de microfunções compiláveis: classificadores, normalizadores, roteadores semânticos e validadores fuzzy podem merecer versão, conjunto de testes e contrato próprio. Mesmo que você não treine adaptadores agora, o padrão de produto é bom: skill textual só vira infraestrutura quando tem especificação, exemplos e avaliação semântica.

Terminal-Universe: Turning Agent Trajectories into Scalable Terminal Environments

A afirmação central é que uma trajetória não precisa ser apenas demonstração congelada: o histórico de comandos revela o workspace suficiente para reconstituir um ambiente reexecutável. O passo interessante é inverter a economia dos dados agentic: em vez de extrair mais exemplos de uma execução, recupera-se o ambiente para gerar novas tarefas, interações e verificações. Para agentes de código, isso é mais valioso que mais transcript limpo.

Para o nosso casoVale olhar para teus próprios traces como fonte de ambientes de regressão: quando um agente resolve algo num repositório, o subproduto deveria ser um snapshot reconsultável, não só uma narrativa final. Isso combina diretamente com trilha de evidência e skills versionadas.

Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning

O resultado que importa não é a técnica chamada Random Attention, mas o diagnóstico: em raciocínio longo, a parte frágil do cache é o prompt; o trace intermediário é redundante no texto e entre attention heads. Isso contradiz a intuição operacional de que é preciso ranquear cuidadosamente cada token de raciocínio preservado. Para quem consome modelo por API, o detalhe de vLLM é menos relevante que a regra de contexto.

Para o nosso casoNa tua compactação de contexto, trate instruções originais, pedido do usuário, constraints e evidência externa como quase intocáveis; já scratchpad, justificativas intermediárias e raciocínio repetido podem sofrer cortes mais agressivos. A ressalva é que isso vale quando o agente reexplicita o que ainda precisa fazer; trace telegráfico demais talvez não tenha a mesma redundância.

LatentPress: Context Compression Beyond Text and Vision

LatentPress leva compressão de contexto para uma representação que não tenta ser legível por humanos: soft tokens lidos diretamente pelo decoder congelado. O dado forte é que, em memória conversacional e QA longo, essa interface supera resumos textuais e até contexto bruto em algumas configurações. A limitação prática é óbvia: isso exige acesso ao embedding interface e um writer casado com o modelo, então não encaixa bem em um harness puramente via API.

Para o nosso casoNada diretamente aproveitavel.

RealSWE: A Compositional Evaluation of Coding Agents under Realistic User Requests

RealSWE é útil porque não apenas ranqueia modelos; ele expõe um mismatch entre SWE-bench e pedidos reais. Prompts reais são curtos, casuais e pobres em estrutura, enquanto os benchmarks clássicos dão issues formais e informativas. O achado acionável é fino: Desired Behavior e Motivation ajudam, enquanto Environment Information e Reproduction Steps podem só gastar tokens sem ganho mensurável.

Para o nosso casoTeu agente primário deveria extrair ou perguntar por comportamento desejado e motivação antes de mergulhar no repositório. Não transforme automaticamente pedido vago em coleta extensa de ambiente; esse paper sugere que nem todo contexto adicional tem o mesmo valor.

Using Grounded Theory for Agent Behavior Analysis at Scale

O ponto aqui é metodológico: usar grounded theory automatizada para descobrir categorias de comportamento em milhares de trajetórias, em vez de aplicar uma taxonomia pré-fabricada. Isso é interessante porque sistemas agentic reais falham de formas locais, dependentes da tarefa, que rubricas genéricas tendem a achatar. O resultado de recuperar 73% a 91% dos modos de falha humanos, além de achar padrões extras, é suficiente para merecer atenção mesmo com poucos upvotes.

Para o nosso casoDá para adaptar a ideia como rotina offline de observabilidade: agrupar traces recentes, gerar codebook de falhas, procurar saturação e transformar categorias estáveis em novos gates ou checks. Isso é mais promissor que pedir ao modelo, execução por execução, uma autópsia livre sem vocabulário acumulado.
