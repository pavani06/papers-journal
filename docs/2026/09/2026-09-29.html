Groupwise Agentic Grading and Advantage Redistribution for Code Agent RL

O ponto importante não é treinar mais um code agent, mas a crítica ao reward binário por testes: duas trajetórias que passam recebem o mesmo crédito mesmo quando uma fez uma mudança limpa e a outra entulhou o repositório. GAGAR usa um grader agentic para ranquear candidatos que passaram nos testes e redistribuir vantagem sem alterar a soma total. Entra também pelo piso de popularização: é um paper muito votado dentro de agentes de código.

Para o nosso casoNo seu harness, isso reforça que “passou nos testes” deve ser só um gate, não o score final. Vale separar evidência executável de avaliação de qualidade: escopo tocado, minimalidade, aderência ao pedido e ausência de efeitos colaterais.

TraceDance: An Automated System for Building Agent Behavior Benchmarks from Real-World Agent Deployment Traces

TraceDance é diretamente alinhado com operação real: pega sessões de deploy e constrói benchmarks para comportamentos indesejados definidos pelo desenvolvedor. A avaliação é feita por continuação em pontos de decisão gravados, com rubrica específica, sem precisar replay completo do ambiente. O resultado prático é uma forma de transformar falhas observadas em testes regressivos de comportamento agentic.

Para o nosso casoEsse é o mais aproveitável do dia para sua trilha de evidência. Você pode adaptar a ideia: marcar decision points em execuções ruins, guardar contexto mínimo e criar evals de próxima ação para regressão de dispatcher, planner e verificador.

WideSWE: Can Coding Agents Coordinate Changes Across Repositories?

WideSWE troca o cenário confortável de um único repositório por tarefas reais que exigem alterações coordenadas em vários repos. O modo de falha é útil: agentes não identificam todos os lugares necessários, começam mudanças e deixam incompletas, ou editam os repositórios certos sem satisfazer o comportamento. A comparação entre execução conjunta e por-repositório sugere que decompor ajuda principalmente a recuperar trabalho omitido, não a consertar implementações ruins.

Para o nosso casoSe o seu sistema algum dia tocar monorepo lógico espalhado em vários repos, trate “quais repositórios são afetados?” como etapa verificável antes de editar. Também vale registrar cobertura por repositório como evidência, não só diff final.

ControlScope: Workflow Revision and Reliability in LLM Agents

ControlScope compara três permissões de revisão: continuar o código gerado, editar argumentos da próxima tool call, ou substituir o workflow inacabado inteiro. O resultado é menos triunfal do que a tese comum de “deixe o agente revisar tudo”: ganhos são pequenos e dependem do domínio, enquanto replays mostram casos em que revisões posteriores interrompem reparos viáveis. Isso é bom porque vira uma pergunta de governança, não de fé em reflexão.

Para o nosso casoVocê pode transformar escopo de revisão em permissão explícita do harness. Antes de permitir replanejamento total, registre qual reparo local foi tentado, qual evidência justifica abandonar o caminho e quanto output será descartado.
