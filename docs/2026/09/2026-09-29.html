TraceDance: An Automated System for Building Agent Behavior Benchmarks from Real-World Agent Deployment Traces

A ideia forte é sair de suites fixas e gerar testes a partir dos próprios traces de deployment, mirando comportamentos indesejados específicos. O benchmark não tenta replay completo do ambiente; ele avalia a próxima decisão do modelo em pontos gravados, com rubrica por comportamento. Isso é bem alinhado com sistemas agentic reais, onde a falha interessante costuma estar no meio da trajetória, não no resultado final.

Para o nosso casoVocê pode copiar o formato: coletar decisões ruins do teu harness, ancorar o contexto mínimo do ponto decisório e transformar isso em eval recorrente para dispatch, verificação e uso de ferramentas. A ressalva é que isso exige rubricas comportamentais bem escritas; sem isso vira só mais juiz nebuloso.

WideSWE: Can Coding Agents Coordinate Changes Across Repositories?

WideSWE mede um modo de falha que SWE-bench normal esconde: feature ou bug fix que exige alteração coordenada em mais de um repositório. O resultado mais útil não é o placar, mas a taxonomia de falha: o agente não encontra todos os lugares, começa a mudança e deixa incompleta, ou altera os repositórios certos sem satisfazer o comportamento. A comparação entre execução conjunta e por repositório sugere que isolar workstreams ajuda mais a recuperar trabalho omitido do que a corrigir implementação ruim.

Para o nosso casoPara o teu sistema, isso vira regra de planejamento: quando uma tarefa menciona ecossistema, contrato, cliente/servidor ou mudança de API, o plano precisa enumerar repositórios afetados e manter uma matriz de conclusão por repo. Também vale criar um gate explícito antes de declarar sucesso: “quais repositórios deveriam mudar e quais testes provam a integração?”.

ControlScope: Workflow Revision and Reliability in LLM Agents

ControlScope separa três permissões de revisão: continuar o código gerado, editar apenas argumentos do próximo tool call ou substituir o workflow inacabado. O achado é incômodo para quem tende a dar liberdade total ao revisor: revisão ampla às vezes conserta, mas também interrompe reparos viáveis e aumenta custo sem ganho líquido claro em todos os ambientes. A fronteira de autoridade importa tanto quanto a qualidade do modelo revisor.

Para o nosso casoIsso conversa diretamente com teus gates: não trate “replanejar tudo” como default depois de uma crítica. Registre o escopo autorizado da revisão — continuar, corrigir argumentos, ou substituir plano — e só eleve para FULL quando houver evidência de que o estado atual está estruturalmente errado.

SkillDRE: Dual-Stage Red-Team Evolution of Agent Skills via Pre-Execution and Runtime Feedback

SkillDRE é relevante porque trata skills como artefatos completos, não como prompts isolados. O ataque evolui em dois estágios: passa pelo scanner pré-execução, roda contra defesas de runtime, usa o resultado para revisar a skill e volta ao scanner. O ponto prático é que uma skill pode preservar a tarefa benigna, escapar de findings estáticos e ainda executar o objetivo malicioso quando observada em contexto.

Para o nosso casoSe você versiona skills como texto, precisa registrar não só diffs e aprovação, mas também resultados de execução adversarial contra runtime real. Scanner estático não basta; o gate de skill deveria incluir uma execução controlada que tenta provar preservação de tarefa e ausência de efeitos colaterais.

TokenCast: Forecasting Token Consumption During LLM Agent Execution

TokenCast ataca um problema operacional simples: o custo final de uma execução agentic muda conforme o próprio agente cria contexto para chamadas futuras. A contribuição é modelar cada segmento pelo consumo próprio e pelo crescimento de contexto que ele impõe aos próximos segmentos. Isso é mais útil que uma média por tarefa porque atualiza a previsão durante a execução sem chamadas extras ao modelo.

Para o nosso casoVocê pode usar a mesma ideia como telemetria de orçamento: cada tool step ou subagente registra custo local e aumento de contexto herdável. O gate não precisa ser “parar aos X tokens”; pode ser “a previsão revisada excedeu o orçamento e o próximo segmento tem baixa evidência de progresso”.

Adaptive Consistency Graph for Long-Horizon Agents

ACG organiza requisitos, evidências, estado e proveniência em um grafo persistente, depois monta uma visão temporária centrada na decisão atual. A novidade operacional é não trocar o planner nem o executor, mas alimentar cada decisão com um recorte rastreável sob orçamento de contexto. O ganho reportado é moderado, mas o desenho é plausível para reduzir drift em tarefas longas.

Para o nosso casoIsso encaixa no teu trilho de evidência: em vez de compactar histórico em resumo livre, mantenha nós de requisito, evidência, decisão e artefato com links de proveniência. Para cada chamada do agente, monte o contexto como uma view derivada do grafo, não como concatenação cronológica.
