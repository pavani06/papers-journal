Avança 04/09

estende a reconstrução de ambientes executáveis para repositórios científicos inteiros com critérios especialistas e trajetórias usadas também para treinamento.

ScienceIDE: Turning World's Scientific Codebase into Agent Learnable Environments

A afirmação central é que código científico legado pode ser convertido em ambientes agentic com tarefas, execução e critérios de aceitação científicos. O ponto novo não é usar repositórios como benchmark, mas fazer agentes transformarem esses repositórios em substratos verificáveis para SFT, RL e avaliação. O resultado de transferência para benchmarks gerais é menos importante para você do que a disciplina de empacotar conhecimento operacional em ambientes executáveis.

Para o nosso casoVale roubar o formato: cada skill ou repositório útil no teu sistema deveria ter casos de aceitação, forma de execução e verificador explícito, não só uma descrição textual. A ressalva é que o modelo deles depende de critérios especialistas; sem isso, o ambiente vira só mais uma coleção de tarefas frágeis.

Confidence Comes from Experience: Experiential Confidence Estimation from Reasoning to Agents

A tese é simples e útil: a confiança de uma resposta não deve sair só da execução atual, mas do histórico de casos parecidos em que o modelo já acertou ou errou. O método guarda episódios com tarefa, reflexão, confiança declarada, resultado e lição posterior; na próxima tarefa, recupera episódios semelhantes e força o modelo a recalibrar. Isso encaixa bem em sistemas por API porque não exige logits nem ajuste de pesos.

Para o nosso casoVocê pode implementar isso como uma memória separada de calibração: após cada execução avaliada, gravar confiança, veredito e lição; antes de ações caras ou irreversíveis, recuperar vizinhos e ajustar retry/escalation. O cuidado é não deixar a própria reflexão virar evidência; o campo decisivo é o resultado graduado.

ProgramDistill: From Interactive Web Apps to Verifiable Reference-Guided SWE Tasks

ProgramDistill avalia agentes quando a especificação vem de interagir com uma aplicação de referência, não de uma issue textual. Isso revela um modo de falha importante: à medida que a profundidade de restauração aumenta, o sucesso cai forte mesmo quando o comportamento correto é executável e replayável. É mais útil do que mais um ranking de SWE-Bench porque testa descoberta de especificação, não só aplicação de patch.

Para o nosso casoAdicione uma fatia de eval em que o agente recebe uma app incompleta e evidências de comportamento da versão correta, depois precisa inferir a feature e provar por replay. Isso testa exatamente a fronteira entre observar, formular requisito e editar código.

Avança 07/09

estende a trilha auditável para um DAG Git de claims rerodáveis com status de verificação e seleção de fronteira.

Agora: Git as Shared Memory for Collective AutoResearch

Agora trata cada resultado, hipótese, insight, verificação e relatório como commit imutável em um DAG, com relações explícitas de dependência. A parte multi-agente importa menos para você, já que teu gargalo é um operador só; o achado prático é o modelo de memória: claims são checkouts rerodáveis, não entradas soltas de log. O índice de fronteira, ramos negligenciados e status de verificação é a peça que transforma trilha de execução em agenda operacional.

Para o nosso casoPara o teu sistema, a lição é registrar claims e verificações como artefatos endereçáveis e reexecutáveis, não apenas como transcript. Um índice de fronteira pode decidir o próximo dispatch melhor do que uma memória cronológica.
