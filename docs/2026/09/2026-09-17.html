Confidence Comes from Experience: Experiential Confidence Estimation from Reasoning to Agents

A afirmação central é que estimar confiança só olhando a inferência atual é insuficiente. O mecanismo guarda episódios anteriores com tarefa, reflexão, confiança declarada, resultado e lição pós-nota; para uma nova tarefa, recupera casos parecidos e força o modelo a reajustar a confiança olhando sua taxa histórica de acerto. Isso é mais interessante que introspecção verbal comum porque ancora a confiança em uma distribuição empírica de falhas do próprio sistema.

Para o nosso casoVale transformar tua trilha de evidência em um índice de episódios graduados por tipo de tarefa, confiança declarada e resultado. O gate humano pode deixar de perguntar “você tem certeza?” e passar a mostrar ao agente suas falhas análogas antes da decisão de ship, retry ou escalonamento.

ProgramDistill: From Interactive Web Apps to Verifiable Reference-Guided SWE Tasks

ProgramDistill avalia agentes implementando features a partir de uma aplicação de referência funcional, não só de issues textuais. O achado relevante é a queda com profundidade de restauração: conforme a feature depende de mais comportamento acumulado, o sucesso despenca mesmo em agentes fortes. Isso revela um modo de falha prático: observar software funcionando não se converte automaticamente em especificação operacional suficiente.

Para o nosso casoPara o teu harness, isso recomenda separar uma skill de “exploração comportamental” antes da edição de código: registrar replays, invariantes e exemplos negativos antes de tocar no patch. Também sugere um eval interno bom: dar ao agente só uma referência executável e medir se ele extrai comportamento antes de implementar.

Avança 07/09

transforma a trilha auditável em um DAG Git de alegações rerodáveis com fronteira e status de verificação.

Agora: Git as Shared Memory for Collective AutoResearch

Agora trata cada resultado, hipótese, verificação e relatório como commit imutável em um DAG, com arestas dizendo dependência e um índice derivado mostrando fronteira e status de verificação. O experimento é em AutoResearch coletivo, mas o formato é mais importante que o domínio: conhecimento agentic como grafo de alegações rerodáveis, não como log narrativo. O risco é o custo operacional de manter granularidade boa; commit demais vira ruído, commit de menos vira ata.

Para o nosso casoPara um operador só, a lição é usar Git não só para artefatos finais, mas para claims intermediários com pais explícitos e verificação associada. Isso pode melhorar teu dispatch: subagente não entrega “resumo”, entrega commit verificável que o agente principal pode checar e herdar.

EvolveTrade: Experience-Driven Policy Refinement for Self-Evolving LLM Trading Agents

Apesar do domínio de trading, o paper é essencialmente sobre tratar o system prompt de um agente com ferramentas como uma política textual ajustada periodicamente por traces e resultado observado. A parte fraca é que retorno financeiro é um sinal ruidoso e cheio de confounders, então não compre o número de Sharpe como evidência geral. A parte forte é a engenharia de loop: separar execução, coleta de feedback, revisão da política e uso da nova versão no próximo lote.

Para o nosso casoIsso é diretamente compatível com teu modelo de skills versionadas: não evoluir prompt em tempo real dentro da mesma execução, mas promover versões entre lotes com evidência anexada. A regra prática é exigir atribuição policy-to-outcome antes de aceitar uma revisão de skill.
